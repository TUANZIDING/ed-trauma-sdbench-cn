# 教学模式设计稿 v0.1 / Teaching mode design

> 状态：设计稿 + 报告生成器已实现（`scripts/teaching-reportv0.1.py`）；交互式学员终端为 v0.2 计划。

## 1. 目标

同一套病例，既评测 AI（A），也训练住院医和医学生（B）。学员与 AI 走完全相同的流程：只看到一句话病例摘要，
通过「提问」和「开检查」向守门人（Gatekeeper）索取信息，最后下诊断，由 Judge 评分、按中文成本表计价。
这样学员的成绩可以直接和模型放在同一张「准确率 × 费用」图上比较。

## 2. 会话流程

1. 选病例：按主题 / 难度 / 病例集（dev 用于练习，test 用于考核）。
2. 开始计时，显示 `case_summary`。
3. 每一轮学员只能选一种动作（与 SDBench `enforce_single_turn_type` 一致）：
   - 提问（每条以 "Question for the patient:" 记录），或
   - 开检查（每项必须是单一可执行的检查，"全套化验"之类会被拒绝），或
   - 下最终诊断（结束）。
4. Gatekeeper 返回结果：病例里有的原文返回；没有的生成合理的正常/非特异结果并标记 synthetic。
5. 结束后 Judge 打分（1–5，≥4 为正确），计价，生成反馈报告。

教学场景可选两种守门人：
- **LLM 守门人**（默认，需要 API key）：复用 SDBench gatekeeper prompt。
- **教师守门人**（离线）：带教老师按病例全文人工回答，系统只做记录。适合小组带教和 OSCE 式考核。

## 3. 记录字段（会话日志，与 SDBench 结果 JSON 同构）

| 字段 | 含义 |
|---|---|
| case_id / case_title | 病例 |
| learner | 学员代号（不写真实姓名，教学单位自行映射） |
| started_at / finished_at | ISO 时间，用于计算用时 |
| requested_tests | 按顺序的全部请求（提问 + 检查） |
| requested_tests_only | 仅检查 |
| test_logs | 每条请求及守门人回答 |
| num_test_rounds | 检查轮数 |
| model_diagnosis | 学员最终诊断 |
| diagnosis_score / diagnosis_reasoning / correct | Judge 结果 |

## 4. 反馈报告内容

1. 总览：诊断得分、是否正确、提问数、检查数、轮数、估算费用（人民币）、用时、关键检查覆盖率。
2. 诊断对照：学员诊断 vs 参考诊断 + 评分理由。
3. 检查与费用明细：每项匹配的价目、单价、来源状态（已核实 / 待核实 / 未匹配）。
4. 教学反馈：遗漏的关键检查；≥200 元的非关键检查（提示反思过度检查）；本例关键线索；应考虑的鉴别诊断；延伸阅读指南。

示例：`examples/demo-sessionv0.1.json` → `examples/demo-reportv0.1.md`（虚构会话，仅演示格式）。

## 5. 评价维度（v0.2 起计划加入）

- 时间敏感性：致命情况（张力性气胸、心包填塞、活动性出血）是否在前两轮内识别；可加"危险延误"扣分。
- 检查顺序合理性：例如血流动力学不稳定时先 FAST/骨盆片，而不是先送 CT。
- 班级汇总：同一病例多名学员的得分分布、平均费用、常见遗漏检查，输出给带教老师。
- 与 AI 同图比较：学员点与各模型点画在同一张准确率–费用散点图上。

## 6. 伦理与使用限制

- 病例全部虚构，不含真实患者信息。
- 价格为公开价格估算，不代表实际收费；报告不作临床决策依据。
- 仅限研究与教学使用（见 README 关于 SDBench 专利申请的说明）。

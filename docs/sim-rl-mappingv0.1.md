# 模拟训练方法映射与分层方案 v0.1

> 状态：草案，供讨论。参考文献：Schmidgall S, et al. *Training language models in simulation for psychiatric intake*. arXiv:2610.40476, 2026-10-29（Google DeepMind 等，CC BY 4.0）。本文只做方法概括与少量短引文，不复制原文图表。

## 结论先行

1. **这篇工作的方法可以几乎一一映射到本项目**：本项目已经有"模拟环境（Gatekeeper）+ 合成病例 + Judge + 成本"的骨架，缺的是三样东西：**安全分类法与对抗病例**、**逐步披露且随时间变化的病人模拟器**、**人类专家双盲评价**。
2. **推荐路径：先做"不训练模型"的评测版（第 0 层），同时做"提示词/检查清单"轻量干预（第 1 层），合成一篇论文；完整强化学习（第 2 层）留给有算力合作方的第二阶段。**
3. 原文最值得借鉴的不是 RL 本身，而是两条教训：
   - 自动评分员与医生评分只有**中等相关**；
   - 用模拟病人评测会**放大效果量**（同一自动评分员下，训练前后差值由 0.21 扩大到 0.34）。
   所以本项目任何结论都必须有**医生扮演病人 + 独立医生盲评**这一层，不能只靠模拟器打分。

## 三、分层可行方案

### 第 0 层：不训练模型，只做评测基准（最现实，推荐首发）

做什么：

- Gatekeeper 升级（逐项披露、检查名规范化、模拟时钟与动态生命体征）；
- 新增"紧急度分级""下一步处置"动作；
- 创伤安全分类法 + 两轮 Delphi；
- 标准病例扩到 60–100 例，对抗病例 64–128 例；
- 评测 3–5 个模型（含国产模型），自动评分 + 抽样医生盲评。

门槛：无 GPU；模型 API 费用约数千元量级（按 3–5 个模型 × 约 200 例 × 3 次重复粗估，实际取决于模型价格，待试算）；人力主要是病例编写与 Delphi 专家。

产出：一篇基准/安全评测论文；同时直接服务教学（学员也走同一套病例）。

### 第 1 层：轻量干预（提示词 / 检查清单 / 自我批评）

在第 0 层基础上，对同一模型比较四个臂：

1. 基础提示词；
2. + ATLS 初级评估检查清单（ABCDE 未完成不得给最终诊断，对应原文"清单阻止过早结束"建议）；
3. + 自我批评迭代（给诊断前先自查"哪些致命伤我还没排除"）；
4. + 多角色编排（SDBench 原文 MAI-DxO 式虚拟专家组）。

门槛：仍无 GPU；API 费用约为第 0 层的 2–4 倍。

价值：回答"不改权重，能把分诊不足降多少"，这正是原文刻意排除的对照（原文只证明 RL 优于相同提示词的基础模型）。这是本项目可以**补位**的地方。

### 第 2 层：完整强化学习

做什么：开源中文模型（如 7B–14B 级）+ 多轮 GRPO（verl / TRL / OpenRLHF 等框架），以升级后的 Gatekeeper 为环境，序贯奖励含成本与时间。

门槛（粗估，需与算力方核实）：

- 算力：多轮对话 RL 需要同时跑策略模型、模拟病人、评分员；7B–14B 全参数通常需 8 卡 80GB 级 GPU 跑数周，LoRA 可降但仍需多卡；
- 数据：原文用约 4.8 万个生成场景，本项目需要自动生成管线 + 医生抽样审核，至少数千例；
- 评分员成本：每条轨迹都要 LLM 评分，费用随轨迹数线性增长；
- 人力：一名熟悉 RL 训练的工程师；
- 合规：开源模型的许可证、训练数据全部合成。

建议：第 0/1 层结果出来后，带着基准和安全分类法去找校内（苏大）或企业算力合作，第 2 层作为第二篇。

### 推荐路径

**第 0 层 + 第 1 层合成一篇（约 6–9 个月）→ 第 2 层作为合作第二篇。**

理由：第 0/1 层不依赖算力，可以直接用于教学，而且回答了一个原文没有回答、对临床更有用的问题：用检查清单这种便宜手段能把创伤分诊不足降多少。

## 四、本项目相对原文的差异化

- **序贯 + 成本 + 时间**：原文只评问诊，不算检查费用和时间；创伤是"时间就是生命"，模拟时钟与动态恶化是原文没有的维度。
- **中文与中国价格体系**：中文对话、江苏/无锡公开价格。
- **A+B 合一**：同一套病例同时评 AI、训练住院医，可做"人机同卷"对比。
